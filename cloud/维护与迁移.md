# 海行维护与项目迁移

## 提交前验证

1. `npm ci` 安装锁定依赖，`npm audit` 检查依赖报告。
2. `npx playwright install chromium` 安装测试浏览器；Windows 已安装 Chrome 时也可直接使用。
3. `npm run check` 验证核心规则、生产构建和两端浏览器交互。
4. 查看变更范围，确认未加入个人学习备份、密码、服务端密钥或本机安装文件。
5. 提交并推送，查看 GitHub Actions 和 Vercel 的发布结果。

测试截图在 `test-results/`，生产资源在 `dist/`，这两个目录由工具生成并已忽略。`vendor/` 中的浏览器 SDK 由构建生成；升级依赖时一起检查构建结果。

## Supabase 转移到另一个管理账号

转移现有项目到目标账号的组织，保留原项目及其数据。操作前导出可恢复的数据库备份，并记录项目 ID、客户端连接地址、Auth 配置、RLS 和现有用户/事件数量。应用内的 JSON 学习备份另行保存。

1. 在来源组织的成员设置中邀请目标账号为 Owner，由目标账号接受邀请。
2. 使用目标账号打开现有海行项目，在 **Settings → General → Transfer project** 选择目标账号拥有的组织。
3. 按控制台提示检查项目转移条件。官方要求操作者是来源组织 Owner，至少是目标组织成员；存在 Supabase GitHub 集成、项目专属角色或 Log Drain 时，需先处理相应限制。
4. 在 General 设置中将显示名称改为 **海行**。核对转移后的项目 ID、连接地址及客户端密钥；按实际结果决定是否更新 `sync-config.js`。
5. 用目标账号确认组织和项目管理权限，再进行功能验收。

转移涉及目标组织的套餐、可用功能和免费项目额度。付费组织转入免费组织可能短暂中断服务。原账号的管理权限在验收完成前保留，便于处理转移问题。

官方说明：[Project Transfers](https://supabase.com/docs/guides/platform/project-transfer)

## GitHub 与 Vercel 改名

- GitHub 仓库使用 `haixing`。本机克隆通过 `git remote set-url origin https://github.com/ECHO0l0/haixing.git` 更新地址。
- Vercel 在 **Settings → General → Project Name** 中改为 `haixing`。
- 检查 Vercel 的 Git 关联、生产分支、环境变量和域名绑定，确认新提交能完成部署。
- 对外网站继续使用绑定的自定义域名；如果调整了访问域名，还需一起更新中转地址、允许来源和 Auth 回调地址。

官方说明：[GitHub 改名](https://docs.github.com/en/repositories/creating-and-managing-repositories/renaming-a-repository)、[Vercel 改名](https://vercel.com/kb/guide/how-do-i-change-the-name-of-my-vercel-project)

## 迁移后真实验收

| 检查 | 通过条件 |
| --- | --- |
| 网站和桌面账号 | 迁移前的学习账号仍能登录，已有资料和记录可见 |
| 账号隔离 | 两个不同学习账号只能读取各自的云端记录 |
| 多端同步 | 手机作答后电脑收到进度，电脑修改收藏后手机收到修改 |
| 练习续接 | 中途退出并重开后保留题目顺序、位置和答案 |
| 个人资料 | 昵称、简介和头像在另一端更新 |
| 离线补传 | 断网作答后联网完成同步，重复同步不增加作答次数 |
| 邮箱功能 | 普通用户收到注册/找回邮件，链接回到正确站点 |
| 页面稳定 | 同步时页面、滚动位置和正在编辑的输入保持稳定 |

模拟测试、认证设置接口可访问和真实账号验收分别记录；只有完成实际登录与数据往返，才能确认迁移后的云端功能。
